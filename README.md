# 会议议程实时重排（Meeting Agenda Live Re-arranger）

会议进行中，某项议程超时结束时，从当前时刻向后自动重排后续议程：

- **固定休息段不移动**：固定开始时间的休息段始终钉在原时间；
- **按优先级压缩**：先压缩优先级低、且非“不可压缩”的议程项，任何项都不会低于其最短时长；
- **冲突明确列出**：即使所有可压缩项都压到最短仍无法容纳时，页面顶部明确列出冲突议程与超出分钟数；
- **一键生成延期建议**：冲突面板可试排“把低优先级议程移出本次会议”，先预览延期项目与试排时间轴，确认后原子保存并立即重排（可撤销）；
- **双时间轴对比**：原计划 vs 实时新计划，压缩 / 完成 / 冲突分段着色，并标注当前时刻锚点与会议结束时间；
- **可撤销**：随时撤销最近一次实况录入（含延期操作，支持逐步撤销），也可一键重置实况。

技术栈：**FastAPI + SQLite（标准库 sqlite3）+ 原生 HTML/CSS/JavaScript**，无前端构建步骤。

---

## 一条命令启动（Docker Compose）

```bash
docker compose up --build
```

启动后在浏览器访问：

> **http://localhost:8000**

- 容器内服务监听端口 **8000**，已映射到宿主机同端口（`8000:8000`）。
- SQLite 数据文件保存在 Docker 卷 `agenda-data`（容器内 `/data/agenda.db`），容器重启后数据不丢失。
- 停止：`docker compose down`（加 `-v` 可同时删除数据卷）。

如宿主机 8000 端口被占用，修改 `docker-compose.yml` 中的端口映射，例如 `"8080:8000"` 后访问 http://localhost:8080 。

## 不用 Docker，直接本地运行

需要 Python 3.10+：

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

访问 **http://localhost:8000** 。数据库默认创建在 `data/agenda.db`，可用环境变量 `AGENDA_DB` 指定其他路径。

## 使用流程

1. **创建会议**：填写标题、开始 / 结束时间。
2. **添加议程项**：每项设置
   - 计划时长、最短时长（压缩下限）；
   - 优先级 `1（最低）～ 5（最高）`，压缩时从最低优先级开始；
   - “不可压缩”勾选后该项保持计划时长，绝不缩短；
   - 可用 ↑ / ↓ 调整议程顺序。
3. **添加固定休息段**：设置固定开始时间与时长（不能与其他休息段重叠）。
4. **录入实况**：会议进行中，在议程列表点“⏱ 实况”，填写该项**实际结束时间**并提交。系统立即：
   - 冻结已完成项；
   - 从该时刻起，把未完成议程依次装入固定休息段之间的空隙，必要时按优先级压缩；
   - 无法容纳时，红色面板列出冲突项与超出分钟数。
5. **生成延期建议（可选）**：存在冲突时，红色面板底部出现“🧹 生成延期建议”。点击后系统**只试排、不写库**：
   - 从最早的冲突开始，每轮按 **优先级低 → 可释放计划时长大 → 原顺序靠前** 选出一项移出本次会议，再整体重排，直到冲突清零或无候选；
   - 固定休息段、已完成项、不可压缩项永远不会被移出；
   - 弹窗列出每一步将延期的项目、释放时长与原因，并展示**试排时间轴**；
   - 若仍有冲突，弹窗明确显示剩余超时分钟数，**“确认延期并重排”按钮禁用**，无法确认；
   - 确认后延期状态原子写入数据库并立即重排；该操作作为一条记录进入撤销链，点“↩ 撤销最近录入”即可把这些项目恢复回本次会议。
   - 已延期的议程在列表中标“⏭ 已延期”，不再参与重排；撤销延期前也不能对其录入实况。
6. **撤销 / 重置**：点“↩ 撤销最近录入”逐步回退；“重置实况”清除全部实际结束时间与延期状态（重置本身也可撤销）。

## 重排规则（算法说明）

- 重排只影响**尚未录入实际结束时间**的议程；已完成项时间冻结。
- 未完成议程按顺序装入相邻固定休息段之间的空隙：
  - 空隙足够时保持计划时长；
  - 空隙不足时，按 **(优先级升序 → 可压缩空间降序 → 原顺序)** 压缩，直到容纳或全部到达最短时长；
  - 某项即便压到最短也放不进休息前空隙时，顺延到休息之后，并生成一条“无法在固定休息前安排”的冲突（注明超出分钟数）；
  - 最后一段空隙以会议结束时间为界，仍超出时生成“超出 N 分钟”冲突，超时段在时间轴上标红。
- 录入的实际结束时间落入固定休息段内时，重排锚点自动顺延到休息结束，并给出提示。

### 延期建议算法

- 候选仅限**未完成、未延期、可压缩**（即未勾选“不可压缩”）的议程；固定休息、已完成项、不可压缩项不可移出。
- 每轮取当前最早的硬冲突（休息前放不下 / 超出会议结束时间；“锚点落入休息”仅为提示，不参与）：
  - 在卷入该冲突的候选中，按 **(优先级升序 → 可释放计划时长降序 → 原顺序)** 选一项移出，再对剩余议程完整重排；
  - 重复直到冲突清零（成功）或冲突已无候选（失败，返回剩余超时分钟数）。
- 预览接口只做试排，不写数据库；确认接口会再次用提交的项目集合完整试算，只有冲突清零才允许原子提交，且整批延期只占撤销链中的一条记录。
- 延期后录入实况会自动跳过已延期项，按剩余议程的顺序校验。

## API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/meetings` | 会议列表 |
| POST | `/api/meetings` | 创建会议 |
| GET | `/api/meetings/{id}` | 会议完整计划（items / breaks / 原计划 / 新计划 / 冲突 / **revision**） |
| POST | `/api/meetings/{id}/items` | 添加议程项 |
| DELETE | `/api/items/{id}` | 删除议程项 |
| POST | `/api/items/{id}/move` | 上移 / 下移（`{"direction":"up"}`） |
| POST | `/api/meetings/{id}/breaks` | 添加固定休息段 |
| DELETE | `/api/breaks/{id}` | 删除休息段 |
| POST | `/api/meetings/{id}/actuals` | 录入实际结束时间并触发重排（提交 `revision`） |
| POST | `/api/meetings/{id}/postponements/preview` | 试排延期建议（不写库）：延期项目、每步原因、剩余超时、试排时间轴、**revision** |
| POST | `/api/meetings/{id}/postponements` | 确认延期（提交预览返回的 `revision`；原子保存 + 立即重排，进入撤销链；版本不一致或仍有冲突返回 409） |
| POST | `/api/meetings/{id}/undo` | 撤销最近一次实况录入 / 延期（提交 `revision`） |
| POST | `/api/meetings/{id}/reset` | 重置全部实况与延期状态（提交 `revision`，可撤销） |

交互式文档：启动后访问 http://localhost:8000/docs 。

### 乐观并发（revision）

会议进行中可能有多个标签页 / 操作员同时操作，因此每个会议维护一个**单调递增的 `revision`**，对实况时间轴采用乐观并发控制：

- `GET /api/meetings/{id}` 的返回中带有当前 `revision`；延期预览接口（只读、不写库）同样在返回中盖上生成该试排时的 `revision`。
- 录入实况（`actuals`）、撤销（`undo`）、重置（`reset`）、确认延期（`postponements`）的请求体必须带 `revision`（非负整数），值取自最近一次读取到的计划 / 预览：

  ```json
  { "...": "各接口原有字段", "revision": 3 }
  ```

- 服务端在**同一个 `BEGIN IMMEDIATE` 写事务内**先比较 `revision`，再写入，成功后把该会议的 `revision` 原子 `+1`；比较失败时事务整体回滚，**不改变任何数据**，返回 `409 Conflict`：

  ```json
  { "detail": { "code": "revision_conflict",
                "message": "计划已被其他操作更新（版本不一致）……" } }
  ```

- 确认延期时校验的是**预览产生的那个 `revision`**：预览确认前若已有其他实况操作（录入 / 撤销 / 重置 / 另一笔延期）改变了时间轴，旧预览的确认必然 409，旧试排结果不可能覆盖新时间轴；冲突后需要重新调用预览接口。
- 前端在 409 冲突提示中会自动重新拉取最新计划；延期确认冲突时关闭旧预览弹窗并引导重新生成延期建议。
- 撤销链为空时撤销返回 `404` 且不改变 `revision`；议程编辑 / 休息段编辑只允许在未开始录入时进行，不参与 `revision`。旧版 SQLite 数据库首次启动会自动迁移补上 `revision` 列（默认 0）。
